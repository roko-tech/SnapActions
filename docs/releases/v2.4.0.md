# SnapActions v2.4.0

SnapActions now supports a searchable keyboard workflow, explicit result destinations, and a browser companion that reads the actual selection. This release also adds local text tools and fixes browser-helper recovery after restarting the desktop app.

## New and improved

- **Keyboard palette:** press Ctrl+Shift+Space, search for an action, inspect the preview, and choose Copy or Replace. Manual text entry is available when a selection cannot be read.
- **Result previews:** transforms work on read-only selections, with an explicit Copy result action and Replace selection for a verified editable target.
- **Browser companion:** optional Brave/Chrome/Edge integration reads selected page/input/frame text directly, carries its direction, and validates the captured document and range before use. Setup, connection health, a local selection sample, and capture timings are available in Settings.
- **Local tools:** offline QR images with copy/export, conservative tracking-link cleanup, Unicode/text inspection, and saved recipes containing up to 12 pure text operations.
- **Settings:** searchable sections, light/dark/system themes, visible autosave results and retry, independent language preferences, and Reading/Writing/Development app presets.
- **Lookup and parsing fixes:** consistent signed currency parsing, strict UTF-8 decoding, explicit translation language pairs and request limits, bounded HTTP responses, cached successful lookups, and useful timeout/retry states.
- **Capture and effects:** selection snapshots, UIA reads, clipboard transactions and guarded input execution have separate responsibilities. Automatic selection capture remains clipboard-free. Toolbar pins and overflow share a width budget, and Paste As respects enabled actions and app profiles.
- **Restart recovery:** the native messaging host exits when the desktop connection closes, including while the browser keeps stdin open, so the companion can reconnect after an app restart.

OCR and AI rewriting remain deferred.

## Upgrade

1. Exit the old SnapActions instance, extract the complete `SnapActions-2.4.0-win-x64.zip` into a permanent location, and run `SnapActions.exe`. Keep its `browser-extension` folder beside it. The .NET runtime is included; existing settings remain under `%AppData%\SnapActions`.
2. For the optional browser companion, follow the [setup instructions](../../browser-extension/README.md). Its first packaged extension version is 1.0.0 and its protocol version is 1. Update/reload an existing unpacked companion when upgrading; an older protocol is rejected. Register the helper again under Settings → Browser if the executable path changed.
3. Transforms now show a result preview. Use Copy result or Replace selection explicitly; the former replacement preference selects the default destination in the keyboard palette for editable selections.

The release assets include a ZIP and `SHA256SUMS`. The ZIP also contains checksums for its executable and companion files.

## Validation and remaining gaps

The package gate runs 483 .NET tests, 12 extension tests, the published executable's UTF-8 native-host tests (immediate/delayed connection and desktop EOF with browser stdin open), and compiled WPF layout/state checks. Release publication follows a successful GitHub Actions run on the release commit; its run link and asset checksum are recorded in the GitHub release.

The pre-release live Windows pass confirmed palette opening, unchanged clipboard sequence during the tested keyboard selections, and real Brave helper recovery after a desktop restart. It exposed the native-host hang fixed in this release. See the [live report](../live-validation-2026-09-07.md) for exact evidence.

Full mouse selection, Copy/Replace and focus-return workflows, stale-target refusal during live effects, Settings/feature interaction, and multiple-monitor DPI transitions remain unverified in the new UI. Native screenshot/mouse automation failed and could not target the floating palette; browser policy also blocked reloading the companion through the extension-management page. Unit tests and compiled renders provide narrower coverage.
