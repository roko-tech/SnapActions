# SnapActions v2.4.2 — toolbar customization and selection safeguards

This release includes the toolbar changes previously tested as local v2.4.1 and v2.4.2 builds, plus the subsequent stabilization work. v2.4.1 was not published separately.

## Changes

- Drag actions from menus onto the toolbar to pin and reorder them. Right-click to pin, unpin, hide or move an action; restore hidden actions from the toolbar's action catalog. Pins retain their order, remain independent of the suggested-action limit and refresh when settings change.
- Native Delete, Paste and Replace require affirmative writable evidence and revalidate the captured selection's exact text and endpoints before input. A changed selection cancels the action. Missing capability evidence disables editing while keeping captured-text actions available.
- Reject Chromium mouse-derived ranges that extend outside the provider's document. This fixes a reproduced VS Code drag that returned an unrelated glyph. Unreliable automatic capture remains unavailable; physical Ctrl+C supplies the exact text when enabled in settings.
- Preserve selected boundary whitespace in browser UIA fallback. Automatic selection capture remains clipboard-free.
- Restore hover previews after closing and reopening menus; bound long preview text and preserve mixed-direction display. Paste uses a compact clipboard icon with its accessible name and explanatory tooltip.
- Use the local-path opener for browser setup buttons, and describe native-host registration relative to the running copy.
- Limit XML formatting to 32,768 input characters and 65,536 output characters, prohibit DTDs and disable external resolution.
- Allow a known failed result Copy to be retried. Cancelled or uncertain replacement attempts remain consumed. Copy and customization remain available when no other action matches.
- Remove QR Code and Inspect Text, their UI and QR dependencies. Settings migration removes their retired IDs while retaining other pins.

## Validation and limits

The reviewed candidate passed **523 .NET tests, 12 browser tests, 10 compiled WPF check categories and 3 published native-host lifecycle cases**, using locked dependencies and warnings as errors. Fetch tests exercise the production lookup service, including UTF-8 byte bounds and stream failures. WPF checks cover failed settings writes/replacements, visible error state and successful retry/reload persistence.

Physical checks covered native selection changes, valid edits and clipboard behavior in Notepad and a WPF fixture. Brave checks passed for Arabic/English with emoji and boundary spaces, exact Copy, stale-selection rejection, valid Delete, read-only controls and reconnect after restarting SnapActions. The [September 8 validation report](../release-validation-2026-09-08.md) distinguishes the live-tested candidate from the final release build and links the earlier receipts. The GitHub release records the final commit, hosted CI result and package checksums.

**Known VS Code limitation:** the tested 1.113.0 screen-reader mode reports a session-read-only editor as writable through UI Automation. Delete/Paste can therefore appear enabled, although VS Code rejected the tested edit and kept the document unchanged. No trustworthy replacement capability signal was found. Default accessibility mode also lacked usable native editing ranges; Ctrl+C remained available for captured-text actions. Automatic Electron capture, all-editor compatibility, mixed-monitor transitions and sustained performance are not certified by these checks.

## Upgrade

Extract the complete ZIP, keeping `SnapActions.exe` and `browser-extension` together. Close the previous desktop copy before starting the new one. Existing settings are retained. If the executable moves, register the helper again in Settings → Browser. Keep the companion files current and reload the extension after updating them; this release retains protocol version 1.
